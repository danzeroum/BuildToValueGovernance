AGENT PSYCHOMETRICS:
TASK-LEVEL PERFORMANCE PREDICTION IN AGENTIC CODING BENCHMARKS
Anonymous authors
Paper under double-blind review
ABSTRACT
As the focus in LLM-based coding shifts from static single-step code generation
to multi-step agentic interaction with tools and environments, there is a growing
need to understand what evaluations of coding agents tell us. At present, agent
performance is typically measured by aggregate pass rates on benchmarks, but
single-number metrics obscure the diversity of tasks within a benchmark. We
present a framework for predicting success or failure on individual tasks tailored
to the agentic coding regime. Our approach augments Item Response Theory
(IRT) with rich features extracted from tasks, including issue statements, repository contexts, solutions, and test cases, and introduces a novel decomposition
of agent ability into LLM and scaffold ability components. This parameterization enables us to aggregate evaluation data across heterogeneous leaderboards
and accurately predict task-level performance for unseen benchmarks, as well as
unseen LLM-scaffold combinations. Our methods have practical utility for benchmark designers, who can better calibrate the difficulty of their new tasks without
running computationally expensive agent evaluations.
INTRODUCTION
As language models become capable of solving longer horizon (Kwa et al., 2025), more complex
tasks, evaluations have shifted from simple question-and-answer tasks to multi-turn evaluations of
a model’s capability as an agent. Nowhere is this transition more pronounced than in software
benchmarking. The problems posed to LLM coding agents are increasingly complex and multistep:
indeed, newer benchmarks like SWE-bench Verified (OpenAI, 2024) and Terminal-Bench (Merrill
et al., 2026) that test how coding agents iterate with execution feedback from tool calls are replacing
static single-step code generation benchmarks like HumanEval and MBPP (Chen, 2021; Austin
et al., 2021).
But the multi-step nature of coding agent benchmarking creates many challenges for benchmark designers. Agentic evaluations are complicated by the interaction of the agent with the environment:
test cases often test for properties of other components of the codebase that are not mentioned in
the problem statement (OpenAI, 2024) or allow underspecified submissions to pass (Wang et al.,
2025), and agentic tasks often have multiple valid solution paths and edge cases that are difficult to
anticipate when designing the evaluation rubric. Worsening the challenge, agentic tasks are often
heterogeneous: agents can fail on different tasks in the same benchmark for different reasons, which
reporting a single number about the agent’s overall solve rate on the benchmark, as is common practice (Anthropic, 2026; OpenAI, 2026), fails to capture. It is useful, both to agent developers and to
benchmark designers, to have a task-level understanding of where agents fail, for improving agent
capabilities and designing more discriminative tasks (Liu et al., 2025). But running a suite of agents
on each item in a long horizon benchmark in order to obtain this kind of task level understanding
can be very expensive; for instance, a single run of Darwin-G¨odel Machine (a self-improving software agent) on SWE-bench Verified cost $22, 000 (Zhang et al., 2025a). This motivates the central
question of this work: how can we efficiently predict agent performance at the task level in agentic
coding benchmarks?

To achieve this, we extend a method of predicting task-level performance called Item Response Theory (IRT) to make use of features of the agents and tasks in the prediction, instead of treating agents
and tasks as generic IDs. IRT is a method from psychometrics for modeling the interaction between
test-takers and exam problems (Baker, 2001). In IRT applied to model evaluations, agents are testtakers with latent ability scores, and benchmark tasks are exam problems with latent difficulty scores
(Hofmann et al., 2025). The success probability of any agent on any task can be predicted as a function of the agent’s ability and the task’s difficulty. Despite their utility, standard IRT methods are
limited by treating each task and each agent as an ID: they require computationally expensive agent
evaluation data for any agent or task before being able to make predictions about its performance,
and offer no insight into what aspects of the task explain its difficulty beyond revealing the difficult
tasks. Our approach to overcoming these limitations builds on the work of Chen et al. (2025) and
Truong et al. (2025), who train models to predict IRT task difficulties from task embeddings, allowing them to predict agent performance on question-and-answer tasks with no evaluation data, given
only the problem statement. We extend their task difficulty predictor as part of our success predictor,
but with different inputs specialized for the agentic coding regime, where as earlier described, an
agent’s success on a task derives from the complex interaction of properties of the agent, task, and
environment.
We find that agent and task features specific to the agentic coding setting, such as the agent’s underlying LLM and scaffold or the task’s test cases, solution patch, and repository state, offer additional
predictive capabilities beyond using just the problem statement. We demonstrate that using these
features, we can meaningfully predict agent success probability on held-out tasks, and even held-out
benchmarks and held-out agents with new LLM-scaffold combinations. Our methods are thus especially useful to agentic coding benchmark designers, who can use our task difficulty predictors to
estimate the difficulty of tasks in their new benchmarks which have no agent evaluation data, instead
of heuristically mentally modeling where agents will struggle.
A summary of our contributions is as follows:
1. Difficulty prediction from agentic task features: We extend task difficulty prediction
from Truong et al. (2025) to agentic coding benchmarks by learning predictors from static
task features (issue text, gold patch, test patch, and repository state).
2. LLM-scaffold ability decomposition for multi-benchmark IRT: We learn an IRT ability
component for each LLM and each scaffold that appears in an agent individually, allowing us to aggregate benchmarks whose evaluation data share few overlapping agents. We
validate the learned LLM abilities by comparison to a fixed-scaffold setting. We demonstrate that the multi-benchmark IRT model can be used to predict performance on held-out
benchmarks and held-out agents whose LLM and scaffold are individually present in the
training response data.

BACKGROUND AND RELATED WORK
2.1
BACKGROUND
2.1.1
AGENTIC CODING BENCHMARKS
In contrast to question-and-answer benchmarks, agentic benchmarks require the LLM to dynamically call tools and explore the environment, eventually submitting a final solution, which is validated via unit tests or observations of the environment’s final state. Agentic benchmarks are especially popular in the coding domain because many programming or software engineering tasks
naturally involve interacting with entire codebases. To function as an agent, an LLM needs to be
augmented with a scaffold, or a framework comprising tools, system prompts, and often a retrieval
system (Grace et al., 2026).
In our experiments, we consider four human-verified agentic coding benchmarks, covering a wide
range of coding skills:
• SWE-bench Verified (OpenAI, 2024) is a human-verified subset of tasks from SWE-bench
(Jimenez et al., 2024), a popular general-purpose software engineering benchmark. The
tasks involve solving real-world GitHub issues from Python repositories.
• SWE-bench Pro (Deng et al., 2025) was intended to be more challenging than SWE-bench
Verified and include a wider variety of repositories while keeping a similar task format.
• Terminal-Bench 2.0 (Merrill et al., 2026) is a challenging benchmark focused on computer
terminal environments.
• GSO (Shetty et al., 2025) is a very challenging benchmark focused on software performance optimization. To succeed, an agent needs to optimize a program in a way that not
only passes the correctness tests but is also at least 95% as fast as the ground-truth (expertwritten) optimization.
2.1.2
ITEM RESPONSE THEORY (IRT)
IRT is a technique from classical psychometrics for analyzing the interaction between test takers
and test problems (Lord, 1968; Baker, 2001). In the simplest IRT model—the one-dimensional oneparameter logistic (1D 1PL) model, also known as the Rasch model—each test taker i has a latent
ability parameter θi and each problem j has a latent difficulty parameter βj (Rasch, 1993). Together,
these parameters determine the success probabilities of test takers on different problems:
P(yij = 1|θi, βj) = σ(θi −βj),
where yij is a boolean denoting the correctness of test taker i’s response on problem j (1 = correct,
0 = incorrect) and σ is the sigmoid function. IRT has been used in standardized tests like the SAT to
provide well-calibrated measures of test-taker ability (Petersen et al., 1982; College Board, 2025).
2.2
RELATED WORK
IRT was first applied in NLP by Lalor et al. (2016), who used the IRT ability instead of the accuracy
score as a better measure of a model’s capability. Later works used IRT to obtain faster evaluations of
LLM ability by evaluating on a dynamically chosen subset of the benchmark data (Maia Polo et al.,
2024; Truong et al., 2025; Hofmann et al., 2025). Truong et al. (2025) and Chen et al. (2025) both
developed methods to estimate task difficulties without response data; in particular, Truong et al.
(2025) used a linear model to predict difficulties from embedding vectors. We adapt their methodology to the agentic coding setting, leveraging features of tasks and test-takers that are specific to
this setting. Truong et al. (2025) also attempted to estimate test-taker (LLM) ability using training
compute cost in FLOPs, but this information is unavailable for many LLMs, especially proprietary
ones. Our agent features—the LLM and scaffold corresponding to each agent—are more likely to
be known.

METHODS
We address IRT’s generalization limitations by extending it to capture informative features of tasks
and agents. This enables us to predict agent performance for new tasks without response data, as
well as (more limitedly) task performance for new agents without response data.
3.1
TASK FEATURE ENCODINGS
We consider two methods of converting a task into a feature vector:
1. embeddings (feeding the task as input into an open-weight LLM and obtaining its embedding vector);
2. LLM-as-a-judge features (prompting an LLM to grade the task according to multiple
pre-defined rubric criteria).
See Appendix A for further details on how we extract the feature vectors.
However, we note that our response prediction methods are compatible with any way to encode a
task into a meaningful vector. In particular, we can concatenate vectors of different types, and we
sometimes find that the resulting performance is better than using each vector alone.
3.2
RESPONSE PREDICTION METHODS
In our experiments, we introduce modifications to the standard IRT model in order to incorporate
task features (see Section 3.1) and agent features (LLM and scaffold; see Appendix B for discussion
of why it’s fair to call the LLM and scaffold “features” for agents)
3.2.1
IRT WITH TASK FEATURES
Following Truong et al. (2025), we fit a linear model to predict a task’s IRT difficulty parameter from
its feature vector. Unlike Truong et al. (2025), who jointly trained the IRT ability parameters and
the weights of the linear model via a maximum log likelihood objective, we first train IRT ability
and difficulty parameters to maximize log likelihood, freeze the IRT parameters, and then fit a ridge
regression model using the features to predict the frozen IRT difficulties. The best regularization
hyperparameter is chosen to minimize 5-fold cross-validation MSE within the training set. We found
the ridge regression to outperform joint log likelihood maximization (see Appendix C.3). We also
consider a wider variety of feature vectors than Truong et al. (2025) (LLM-as-a-judge features and
concatenated vectors in addition to embeddings). When concatenating vectors, we use a different
regularization hyperparameter for each feature source, since the vectors may have very different
dimensions.
3.2.2
IRT WITH AGENT FEATURES
We incorporate agent features differently from task features: extracting numerical feature vectors
from agents based on text inputs, as we do for tasks, would be complicated due to the lack of
standardized textual descriptions of agents and the limited availability of information on proprietary
agents. Rather, we decompose an agent’s IRT ability into the abilities of its underlying LLM
and scaffold. Doing so allows us to “stitch together” multiple benchmark leaderboards and train
multi-benchmark IRT models: although agents (LLM-scaffold combinations) rarely overlap across
different leaderboards, individual LLMs and scaffolds overlap much more frequently.
We relate the two ability parameters via summation because this yielded the best performance among
all functional forms we tested (see Appendix C.2). Under the proposed IRT model, the probability
that LLM m combined with scaffold s succeeds on task j is given by
P(ymsj = 1 | θm, θs, βj) = σ(θm + θs −βj).
(1)
This approach allows us to predict responses for new LLM-scaffold combinations, as long as the
LLM and scaffold were individually seen in the training data. If we combine Equation 1 with task
features (Section 3.2.1) by training a linear model to predict βj from task features, we can also
predict responses on new tasks from held-out benchmarks.

We note that this approach cannot account for agents with multiple or undisclosed LLMs; we exclude
such agents from the experiment. At evaluation time, the approach cannot generalize to agents with
unseen LLMs and/or scaffolds, which we also exclude.
EXPERIMENTAL STRUCTURE
The broad goal of our experiments is to find task and agent features that are predictive of agent
success on a task. We measure the quality of our features by using them to predict success probabilities on held-out sets of responses that are chosen to test a generalization property of our predictor.
Following Truong et al. (2025), our main evaluation metric is AUC-ROC, which we define in more
detail in Appendix F.
All our experiments follow the same structure:
1. Hold out a set of responses (the yij booleans denoting whether or not an agent succeeded
on a task; see Section 2.1.2).
2. Train a predictor (IRT with task features, agent features, or both; see Section 3.2) on the
remaining responses.
3. Use the trained predictor to obtain success probabilities on the held-out responses.
4. Evaluate the predicted probabilities via AUC-ROC.
The experiments primarily vary in what set of responses is held-out. The full description of each
experimental setting is provided in Table 1.

Where applicable, we compare our methods against a naive baseline. For held-out tasks and benchmarks, the baseline predicts each agent’s empirical success rate from the training data (or the LLM’s
empirical success rate ignoring scaffold if the method involves LLM-scaffold decomposition). For
held-out agents, it predicts each task’s empirical solve rate. We also compare our methods against
an oracle IRT, trained on all the data including the held-out responses and serving as an upper bound
on performance.

Benchmark settings evaluate our methods in more realistic and challenging use cases. Below, we
discuss further experimental details specific to each setting.
New Tasks: We investigate if agentic task features beyond the task statement help explain difficulty.
In order to test this, we hold out a subset of tasks and use IRT with task features (Section 3.2.1) to
predict their difficulties. To isolate the effect of each feature source, we extract task feature vectors
from inputs with progressively more feature sources (statement-only, statement + repository state,
etc.) and measure performance each time. In this setting, we also explore if concatenating embedding and LLM-as-a-judge vectors can provide better performance than either alone. We perform the
feature source ablation on SWE-bench Verified and the concatenated feature vector test on every
benchmark; all ROC-AUC scores are reported as averages from 5-fold cross-validation.
New Responses: We evaluate the quality of our model of agent ability as the sum of LLM and
scaffold abilities. To this end, we compare our IRT with agent features (Section 3.2.2) against
standard 1D 1PL IRT on predicting held-out yij observations. We conduct the experiment on every
benchmark (we are restricted to using a single benchmark at a time because standard IRT has too
few overlapping agents to train on multiple benchmarks) and report 5-fold cross-validation averages.
New Agents: We test how well IRT with agent features generalizes to unseen LLM-scaffold combinations. To do so, we hold out a subset of agents and use IRT with agent features to predict their
responses on tasks. In each fold of a 5-fold cross-validation, we filter the held-out set to keep only
agents whose constituent LLM and scaffold appear in the corresponding training data, ensuring that
both components are observed individually but not jointly. We then evaluate AUC-ROC on the filtered test set and report scores averaged across folds. We perform this experiment on SWE-bench
Verified and Terminal-Bench 2.0 because the other two benchmarks (SWE-bench Pro and GSO)
evaluate each LLM with the same fixed scaffold, so any new agent would have a new LLM.
New Benchmark: We evaluate IRT with task and agent features in the most challenging setting,
where it has to generalize to both out-of-distribution tasks and unseen LLM-scaffold combinations.
We train a multi-benchmark IRT model with task and agent features on three benchmarks and evaluate it on a fourth, held-out benchmark (filtering out agents with novel LLMs and/or scaffolds).
We perform the experiment twice, with SWE-bench Pro and GSO as held-out benchmarks, because
SWE-bench Verified and Terminal-Bench 2.0 have many benchmark-specific LLMs and scaffolds.
This experiment most closely resembles the benchmark designer use case: a benchmark designer
would likely use a trained multi-benchmark IRT model on their new benchmark, running agents
with a fixed scaffold (as is the case in SWE-bench Pro and GSO) where not every particular combination of model and scaffold that they run appears in the training data.

5.2
THE LLM AND SCAFFOLD OF AN AGENT ADDITIVELY PREDICT ITS ABILITY TO
COMPLETE TASKS
In the New Responses setting, we validate our model/scaffold decomposition of agent ability by
comparing IRT with agent features to standard IRT on held-out response prediction.
The results of the experiment are shown in Table 4. We see that IRT with agent features performs
comparably to standard IRT on predicting held-out responses within the same benchmark, while enabling multi-benchmark training and predictions (also with high performance), which standard IRT
cannot do. The comparable performance notably supports the hypothesis that LLM and scaffold ability are additive: by decomposing agent ability into LLM and scaffold ability, our multi-benchmark
IRT is now strictly less expressive than standard IRT, as each agent still has only one (summed)
scalar ability value for all task evaluations, but there are now extra constraints on the abilities of different agents due to the sharing of LLMs and scaffolds. The fact that performance is similar means
that the LLM and scaffold abilities are still able to accurately represent the agent’s true ability when
added together.
We further validate the decomposition via a qualitative inspection of learned parameters (Appendix
E) and a comparison of learned LLM abilities in multi-scaffold and fixed-scaffold settings. For the
latter, we leverage SWE-bench Bash Only, which contains the same tasks as SWE-bench Verified
but runs every LLM using the same fixed scaffold (Jimenez et al., 2024). Hence, if we train a
standard IRT on the response data from SWE-bench Bash Only, the ability of the agent should be
roughly the same as the ability of the LLM in the 4-benchmark IRT (we can’t use only SWE-bench
Verified because of the poor overlap of LLMs). For the overlapping LLMs in the two benchmarks,
we plot in Figure 2 the learned IRT LLM abilities from SWE-bench Bash Only against the learned
LLM abilities from training using our model-scaffold decomposition. We see a strong correlation
between the two, validating our interpretation of the LLM ability parameter.

DISCUSSION
Lack of causality. In this work, we begin to open up the black box of what makes a task difficult. We
show that agentic task feature sources like repository state, test patches, and solution patches offer
extra predictiveness of the difficulty of the task beyond the problem statements that were used for
difficulty prediction in the question-and-answer regime. Unfortunately, by posing our experiments
as prediction problems, we cannot infer any causality; we cannot distinguish whether these agentic
features offer a clearer view on information that is already available in the problem statement, or if,
for instance, the thoroughness of the test patch actually contributes to the difficulty of the problem.
We suspect that we are in the latter case; qualitatively, we observe the SWE-bench Verified test
patches to have varying degrees of thoroughness. In addition, our LLM-as-a-judge prompt is written
so that grading the agentic task features requires knowledge of the environment or test patch or
the solution patch explicitly, further decreasing the probability that these task features are simply
illuminating the problem statement.
Agent features. The claim that agents consist of a model and a scaffold is almost trivially true; our
surprising result is that LLM and scaffold abilities are (approximately) additive, without introducing pairwise interaction terms. This independence is critical for comparing different agents across
benchmarks, allowing us enough data to train a multi-benchmark IRT model. The ability scores that
we extract from the scaffolds are interesting in their own right, as no such quantitative ranking of
scaffolds has been done before. We provide these ability scores in Appendix E in Table 12. Some
of the rankings were surprising to us. For instance, Claude Code ranks surprisingly low, but this is
true to the response data.
The held-out agent application is limited by requiring the LLM and scaffold of the held-out agent
to both have existing responses in the training data. This is a fundamental consequence of LLM
and scaffold currently being categorical features. In the future, we hope to find easily accessible
quantitative or semantic agent features, so that we can fully predict the performance of new agents
by extracting these features from them.
Applications of success prediction. We are very excited about the demonstrated potential of our
multi-benchmark success probability predictors to generalize to out-of-distribution coding tasks with
a slight but expected drop in performance, as well as to in-distribution tasks with very good performance. Beyond the benchmark designer use case, our difficulty predictor can also be used to choose
tasks for RL rollouts more efficiently as in Zheng et al. (2025): it is efficient to choose tasks for rollouts for which the probability of success is not too low or too high, to avoid getting zero advantage
and hence zero updates.

DETAILS ON TASK FEATURE EXTRACTION
A.1
EMBEDDING FEATURES
We embed the task, followed by its “gold” solution and an instruction sentence, using an instructiontuned LLM. We extract embeddings from the last layer’s hidden state via last-token pooling, as this
is the standard practice with autoregressive LLMs (Zhang et al., 2025b;c; Li et al., 2025). We
use DeepSeek-R1-Distill-Qwen-32B (Guo et al., 2025) as the embedding backbone, as we
found it to produce the best embeddings among the 17 backbones we tested (see Appendix C.1).
We provide the input template in Appendix G.1 and verify the usefulness of the solution through an
ablation (see Table 2).
A.2
LLM-AS-A-JUDGE FEATURES
We prompt Claude Opus 4.5 (Anthropic, 2025) to assess tasks along a fixed rubric of manually
specified criteria, such as the complexity of the required fix or the ease of verifying its correctness.
For each criterion, we use a discrete scale. In the prompt, we include the task statement, metadata
about the task like its category (for Terminal-Bench 2.0 tasks) or repository (for SWE-bench Verified
tasks), “gold” solution, and unit tests. We additionally give Claude Opus 4.5 shell access to a Docker
container with the task repository through Inspect (UK AISI, 2024), so that it can read and run the
code for better-informed judgments. We provide the prompt template in Appendix G.2 and conduct
ablations on the included components (see Table 2).

B
AN ALTERNATIVE INTERPRETATION OF AGENT FEATURES
In sections 3.2.1 and 3.2.2, we seemingly incorporate task features (numerical vectors extracted
using embeddings or LLM-as-a-judge) and agent features (the categorical LLM and scaffold) differently into the IRT model. For the former, we replaced the IRT difficulty with a linear combination
of the task features. For the latter, we directly replaced the IRT agent abilities by new ability parameters, one for each LLM and one for each scaffold. We now point out that introducing new LLM
and scaffold abilities is mathematically equivalent to using a linear combination of the concatenated
one-hot vectors for LLMs and scaffolds. If LLM m has ability θm and scaffold s has ability θs, then
setting the weight corresponding to the index for m on the concatenated one-hot vector to θm and
the weight corresponding to the index for s to θs results in the same estimated agent ability θm +θs.
This mapping is very easily reversible, so it is a bijection.
This perspective restores the symmetry in our treatment of task features and agent features in the
functional form of IRT. The only remaining difference is the way we choose to train the parameters:
we train using a ridge regression for task features, while we train directly to optimize log-likelihood
for agent features. This choice was made empirically, and we did try training to optimize log likelihood for task features in Appendix C.3.

F
AUC-ROC METRIC DESCRIPTION
The area under the receiver operating characteristic curve, or AUC-ROC, is a number from 0 to
1 that measures how well the model captures true positives while avoiding false positives, with 1
being a perfectly accurate model and 0.5 being the expected score of random guessing. The other
way to interpret AUC-ROC is: given a true successful agent run and a true failing run, what is the
probability that the success probability predicted for the successful run is higher than the success
probability predicted for the failing run.
The AUC-ROC has two advantages over accuracy: it is robust to class imbalance, and it doesn’t
require a fixed threshold on the predicted probability between predicting success and predicting
failure.

H
POOR IRT DIFFICULTY CALIBRATION ON ZERO-SOLVE TASKS
A notable limitation of IRT (besides lack of generalization to unseen tasks and test-takers) is its
failure to produce meaningful task difficulty scores for certain response patterns, such as every testtaker getting a task wrong (Mislevy, 1986). Yet no prior study applying IRT to model benchmarking
addresses this weakness of IRT on zero-solve or near-zero-solve tasks.
Our goal in this section is to confirm that IRT struggles to calibrate difficulties specifically for tasks
with few solves in the responses. We first develop an experimental process to test this.
One of the main challenges for this experiment is how to rigorously evaluate methods that predict
difficulty of currently unsolved problems in terms of how difficult they will be to future agents, as
we have no way to obtain data about future agents’ evaluations and responses. Our main strategy
to do this will be through back-testing, by holding out agents from after a specific date cut-off for
each benchmark. This way, during evaluation time, we do actually have oracle knowledge about the
future using these held-out agents.
Another challenge is how to choose the evaluation metric. Since we’re using held-out agents (some
of whose models and scaffolds are unseen during training) for the evaluation, during training time,
we don’t learn IRT ability scores for these agents, so we can’t plug into the IRT formula to predict
their probability of success. We also can’t use the abilities from an Oracle IRT trained on all of
the agents, since the scale of the predicted difficulties will be different from the difficulty scale of
the Oracle IRT, due to training on a different set of agents. We solve this by noting that AUC is
inherently a relative metric: given a successful (agent, task) pair and a failing (agent, task) pair,
AUC measures how often we predict a higher probability of success for the former than the latter. If
we fix an agent, then for two different tasks with predicted difficulties b1 and b2, the IRT predicted
probabilities of passing those tasks, σ(θ−b1) and σ(θ−b2), are monotonic with respect to difficulty.
Therefore, if we use the mean per-agent AUC, only comparing evaluations of the same agent on
different tasks, we can get around the limitation of not knowing the IRT abilities of the held-out
future agents. This is equivalent to the scikit-learn function roc auc score (average=’macro’), with
agents as the columns and tasks as rows of the predicted response probability matrix. This metric
inherits the ROC-AUC interpretable baseline of 0.5 for random guessing.
In order to show that the lack of successful responses of pre-cutoff agents on hard tasks is what
causes poorly calibrated IRT difficulty estimations for these tasks, we vary the tasks that we evaluate
the modern agents on, loosening the requirement that no pre-cutoff agent can solve any of them.
Specifically, we evaluate the post-cutoff agents on tasks where pre-cutoff agents collectively have a
solve rate of ≤X%; in the standard zero-solve setting, X = 0.
H.1
RESULT: IRT-BASED METHODS STRUGGLE WITH DIFFICULTY PREDICTION ON
LOW-SOLVE TASKS
We plot in Figure 5 the performance of the standard IRT trained on just the pre-cutoff agents, as
well as the Oracle IRT trained on all agents, as the upper threshold X for the solve rate by pre-cutoff
agents on the definition of “frontier” tasks, X ranges from 0% to 30%. I.e., as X increases, the set of
tasks that are used for evaluation have more and more successes in the training response data. We see
that the baseline IRT performance consistently improves as X increases, corresponding to adding in
more tasks that have a higher solve rate by pre-cutoff agents. This is evidence that the challenging
part of making difficulty predictions on hard tasks is the lack of successful agent attempts on them.
To support the claim that the low solve rate and not the fact that we’re evaluating on inherently
difficult tasks is responsible for the poor predictions of IRT, we perform the same evaluation using
tasks in SWE-bench Verified which are annotated as taking either 1-4 human hours or > 4 human
hours (the two hardest labels in the dataset) as our “frontier” tasks. Only 9 out of 45 of these tasks
actually have zero solves. We find that on these tasks, the baseline IRT gets 0.915 per-agent mean
AUC, while the oracle IRT gets 0.938 AUC, a much smaller gap than we observe for the zero-solve
tasks.
