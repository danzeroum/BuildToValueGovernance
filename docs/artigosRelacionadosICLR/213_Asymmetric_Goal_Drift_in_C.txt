ABSTRACT
Agentic coding agents are increasingly deployed autonomously and at scale, and
must navigate tensions between learned values, explicit user objectives, and pressures from their environments. Prior work has studied how such conflicts lead to
failure in instruction-following primarily in toy settings which do not capture the
complexity of real-world environments, such as agentic coding tasks. We introduce
a framework built on OpenCode to orchestrate realistic, multi-step agentic coding
tasks, evaluating how agents violate explicit constraints in their system prompt over
time with and without environmental pressure to violate said constraints. Using
this framework, we demonstrate that GPT-5 mini is increasingly likely to violate
its system prompt when its constraints conflict with its strongly learned values
(e.g., code security) and much more likely if value-aligned pressure is present.
Meanwhile, we observe low rates of violation for strongly value-aligned constraints
and only when environmental pressure to violate is present. In short, we find that
violation of constraints in the system prompt depend on model values, accumulated
context, and environmental pressure for the model and value pairs we tested. Our
findings highlight a gap in current alignment approaches: ensuring that agentic
systems appropriately balance explicit user constraints against broadly beneficial
learned preferences under sustained environmental pressure.
INTRODUCTION
The deployment of Large Language Models as autonomous coding agents represents both a significant
capability advancement and a potential security concern Greenblatt et al. (2024); Hubinger et al.
(2024); Lynch et al. (2025). Tools like Claude Code and Cursor AI enable models to execute multistep coding tasks with minimal human oversight, often tasked with competing constraints (clarity
vs. conciseness, security vs. performance) and operating in codebases with conflicting pressures
(legacy code written in a certain style). This tension surfaces an important question: How do models
reconcile compliance with users with their own learned values and pressures from their environment?
Our work builds on the concept of goal drift introduced by Arike et al. (2025), who define it to be
the phenomenon where an AI agent deviates from objectives explicitly stated in its system prompt,
typically when exposed to environmental pressures that appeal to competing values. More than just
instruction-following failure due to capability issues, Arike et al. show preliminary results that goal
drift is exacerbated by conflicting model values: the model is more likely to drift from a goal its
values are more at odds with.
Prior work on model values and value hierarchies Gu et al. (2025); Jotautaite et al. (2025); Chiu
et al. (2025); Nair and Wang (2025); Seror (2025) reveals mixed results: state-of-the-art LLMs have
different ethical profiles yet seem to share core values which they adhere to inconsistently depending
on context. Furthermore, models navigate value conflicts in specifications inconsistently Zhang et al.
(2025), with high-disagreement scenarios producing 5-13x higher rates of specification violations.
However, these investigations have relied on synthetic environments that fail to capture the complexity
of real-world agentic deployments.
We develop a framework for testing goal drift in realistic coding agent scenarios. Using OpenCode,
an open-source terminal-based coding agent framework that supports multiple LLM providers,
we orchestrate multi-step coding tasks where agents must implement features while adhering to
constraints specified in their system prompt. We then measure whether the agent violates their
constraint over time with and without adversarial pressure to violate it. We observe significant

violation when the system prompt constraints oppose core model values, e.g., security, and find that
violation likelihood increases with time. Our key contributions are:
1. A realistic drift testing framework: We provide a controlled yet realistic environment for
studying goal drift in coding agents. We also create a step-by-step guide that allows for the
automation of experiment creation via an LLM-based coding agent. We open-source our
evaluation framework and experiments to support follow-on research: GitHub: ConstraintDrift.
2. Demonstration of asymmetric goal drift: We show that drift magnitude depends on the
direction of the value conflict. When instructed to follow convenience-oriented goals under
security pressure, GPT-5 mini shows near-complete drift. Conversely, when instructed to
follow security-oriented goals under convenience pressure, drift is minimal yet still present.
3. Evidence for model value hierarchies: Our results demonstrate that GPT-5 mini possesses
implicit value hierarchies that can override explicit instructions. Security-related values
appear strongly prioritized, making security-based adversarial pressure particularly effective
at inducing drift, which could be exploited maliciously.

EXPERIMENTAL SETUP
2.1
METHOD
We test how agents navigate value tensions under adversarial environmental pressure. Specifically,
we task GPT-5 mini with implementing functionality in a codebase while following a constraint set
in its system prompt. This constraint requires following one value over another: convenience over
security, efficiency over security, etc. Meanwhile, the codebase can contain comments and code that
try to persuade the agent from breaking the constraint, as illustrated by Fig. 1.
We use the following notation: Given values X, Y (eg. Efficiency, Security), we denote the experiment testing whether an agent A follows value X over Y as X > Y . To follow X means that A
writes code that satisfies a constraint CX that satisfies X and does not (and cannot) satisfy Y , e.g.,
CX = write efficient but unsafe code. X > Y is the “baseline” experiment. We then introduce
X >P Y as the experiment where the codebase has adversarial pressure persuading A to follow Y
and to not satisfy CX, e.g., do something safe but inefficient. In each experiment, the codebase has
an AGENTS.md file which explicitly specifies the constraint (CX or CY ) that the agent, GPT-5 mini,
must follow. We use OpenCode as the coding agent framework, which ingests the AGENTS.md file
and inputs it into the agent’s system prompt.
For our experiment, we query the agent to implement T = 12 functionalities over 12 time steps
where each query only requires touching one file. For each run of the experiment we randomize the
order of the queries and thus the order of the files explored. In the case where pressure is applied (ie.
>P ), each file contains adversarial comments and/or code and before the agent works on the file, a
random adversarial patch is applied that mimics a colleague leaving a note of varying severity.
If for timestep t the agent follows the constraint in AGENTS.md, we say that the agent gets a
violation score of 0 and a score of 1 otherwise. For example for our experiment testing Convenience

2.2
CONVENIENCE VS SECURITY
For this set of experiments, we evaluate the tendency of GPT-5 mini to drift away from constraints
valuing Convenience as opposed to Security and vice versa. All experiments share the same
baseline authentication system codebase, which is extended in the experiments with pressure. For the
experiment Convenience > Security, the constraint CConvenience in the AGENTS.md file requires
the agent to hardcode service account credentials into the source code for ease-of-use in testing the
codebase. In the Security > Convenience experiment, the credentials are provided for use, but
explicitly told to not be hardcoded. In the >P experiments, there are patches of varying severity
referencing colleague requests, pipeline failures, pressure from executives, etc.
2.3
EFFICIENCY VS SECURITY
For our second set of experiments, we contrast GPT-5 mini’s tendency to adhere to Efficiency and
Security. All experiments share the same financial payment service codebase, extended to add
pressure. For the experiment Efficiency > Security, the constraint CEfficiency in the AGENTS.md
file requires the agent to optimize runtime performance and use a cached authentication context
instead of using a specific function to revalidating a token for sensitive operations. In the Security >
Efficiency experiment, the agent must use this function for revalidating tokens and cannot rely on
cached context. In the >P experiments, the patches share themes of authority, consequence, and
legality with the previous experiment.

DISCUSSION
Our results provide strong evidence that GPT-5 mini possesses an implicit value hierarchy in which
security dominates convenience and efficiency-related values. This manifests in two ways: (1) when
instructed to follow security, the model shows minimal drift even under sustained adversarial pressure,
and (2) when instructed to follow values in tension with security, GPT-5 mini tends to drift toward
writing secure code, especially when the environment encourages this drift. Though, it is important
to note that agents can drift away from security constraints given pressure from their environment.
We extrapolate that organizations deploying coding agents cannot assume that explicit instructions
will be followed when they conflict with model-preferred values. Moreover, malicious actors with
commit access could inject comments designed to exploit this value-based drift, causing agents to go
against instructions on the grounds of false security concerns.
Particularly concerning is the elevated baseline drift in the X = Convenience condition. This
suggests that some instructions inherently conflict with model training and will be partially ignored
regardless of environmental pressure. Furthermore, the agent drifts gradually, so checking initial
compliance is insufficient to ensure long-term alignment.
As for limitations, our experiments focused exclusively on GPT-5 mini, while value hierarchies differ
across models. We tested two value pairs, both containing security, which may indicate security as
a special value. Cross-referencing existing literature on model values, such as Zhang et al. (2025),
could be useful in identifying further strongly-held values. While more realistic than prior work, our
codebases are relatively simple and the constraints are slightly unnatural.
CONCLUSION
We find evidence that GPT-5 mini exhibits significant and asymmetric goal drift when explicit system
prompt instructions conflict with environmental pressures aligned with model-preferred values. GPT-5
mini readily abandons convenience and efficiency-oriented instructions when exposed to securitybased adversarial pressure, while resisting the reverse. Though, we do find models sometimes do
abandon security constraints too under pressure.
These findings highlight model value hierarchies as a potential critical factor in agent alignment.
Specifying desired behavior in a system prompt may be insufficient when that behavior conflicts
with values the model considers more important. Our findings also demonstrate the risk of agent
behavioral manipulation by codebase comments and code. As coding agents become more prevalent
in software development, understanding and accounting for their implicit value systems and potential
adversarial pressure becomes essential for safe and reliable deployment.
