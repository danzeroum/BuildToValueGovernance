HEALTHADMINBENCH:
EVALUATING COMPUTERUSE AGENTS ON REALISTIC HEALTHCARE ADMINISTRATION TASKS
Anonymous authors
Paper under double-blind review
ABSTRACT
Healthcare administration accounts for $1 trillion of annual spend, representing
an ideal application for LLM-based computer-use agents. While clinical applications of LLMs have received significant attention, no benchmark currently exists
for evaluating LLMs on end-to-end administrative workflows. To address this gap,
we introduce HEALTHADMINBENCH, which consists of four realistic GUI environments (an EHR, two payer portals, and a fax system) with 70 expert-defined
tasks including insurance verification, prior authorization, clinical reasoning, and
medical equipment ordering. Each task is annotated with fine-grained, verifiable success criteria, totaling 947 unique points of evaluation. We evaluate six
frontier computer-use agents under multiple prompting and observation settings.
The best-performing agent on full-task success, Claude Opus 4.5, successfully
completes only 22.9% of tasks, while Gemini 3 attains the highest subtask success rate (76.4%), revealing a substantial gap between current agent capabilities
and the demands of real-world administration work. Across models, documenthandling subtasks remain the lowest-performing category, with five of six models
achieving under 20% accuracy, making cross-application data transfer the dominant source of failure. HEALTHADMINBENCH establishes a rigorous foundation
for measuring progress toward safe, reliable automation of high-stakes healthcare
administrative tasks, and we welcome future contributions from the community.
INTRODUCTION
The application of large language models (LLMs) in healthcare has primarily focused on clinical
tasks such as diagnostic reasoning and triage (Arora et al., 2025; Bedi et al., 2025). In contrast, little
academic attention has been paid to administrative tasks (e.g. prior authorization, claims submission,
patient intake), which cumulatively cost our healthcare system $1 trillion per year (Sahni et al., 2023)
and lead to hundreds of thousands of deaths due to preventable medical errors (Makary & Daniel,
2016; Rodziewicz et al., 2024). These administrative tasks typically involve executing complex,
multi-step workflows on legacy software that cannot be directly automated due to a lack of API
support. LLM-based computer-use agents (i.e. models that can observe and interact with computer
software) offer a promising solution to this administrative crisis.
A key challenge, however, has been the absence of a realistic benchmark that captures the complexity
and nuance of automating administrative healthcare tasks. While many benchmarks for computeruse agents have been published for consumer websites (Zhou et al., 2023; Deng et al., 2023; Garg
et al., 2025; Xu et al., 2025) and general enterprise software (Drouin et al., 2024), no benchmarks
have been published that accurately reflect enterprise healthcare software. A core reason is these
systems’ lack of public documentation, gated access, and sensitive data.
Several works have tried to address these issues, such as MedAgentBench (Jiang et al., 2025) and
MedHELM Bedi et al. (2026). While the former created an interactive environment for LLM agents,
it only contains clinical tasks that can be solved via Fast Healthcare Interoperability Resources
(FHIR) API calls and does not support computer-use agents operating over graphical user interfaces (GUIs). Similarly, while MedHELM (Bedi et al., 2026) provides a comprehensive evaluation
framework for medical tasks which includes administrative tasks, it only supports static evaluation

To address this gap we introduce HEALTHADMINBENCH, the first benchmark, dataset, and
repository of interactive environments for training and evaluating computer-use agents on
administrative healthcare tasks. Our benchmark focuses on the Healthcare Administration and
Workflow task category as defined in MedHELM (Bedi et al., 2026), but uniquely operationalizes
these task definitions into concrete, multi-step GUI-based workflows.
Building on the REAL framework (Garg et al., 2025), we develop four deterministic web environments to simulate key administrative interfaces (an electronic health record (EHR) portal, two payer
portals, and a fax portal) and define 70 expert-defined tasks spanning patient verification, prior authorization, chart-based clinical reasoning, and durable medical equipment (DME) ordering. We
provide verifiers (LLM-based and deterministic) for 947 distinct subtasks within these 70 tasks. In
experiments with six frontier LLMs, including Claude Opus 4.5, Gemini 3, and GPT-5, the strongest
agent (Claude Opus 4.5) achieves a 22.9% full-task success rate. Our analysis identifies document
handling and cross-application data movement as key challenges for current models.
Our contributions are as follows:
1. Realistic environments for 4 enterprise healthcare applications. We publish four deterministic computer-use environments to replicate common administrative interfaces, including an EHR, payer authorization portals, and a fax portal. These environments serve as
reproducible proxies for proprietary administrative systems that are not publicly accessible,
and can be used for both training and evaluation.
2. Benchmark of 70 specialized administrative tasks. We curate a dataset of 70 multi-step
administrative tasks from domain experts, covering the MedHELM Administration and
Workflow category. We algorithmically verify whether a task is completed successfully
by decomposing each task into a set of subtasks, where each subtask is a concrete step
that can be checked using either a JMESPath query (a JSON query language for extracting
structured fields from agent outputs) or an LLM judge. These annotations enable finegrained assessment and can be used to construct rewards for agent training.
3. Empirical analysis of 6 frontier agents. We evaluate Claude Opus 4.5, Gemini 3, GPT-5,
Kimi K2.5, Llama 4 Maverick, and Qwen-3-VL on HEALTHADMINBENCH. The bestperforming model, Claude Opus 4.5, achieves a 22.9% success rate on end-to-end task
completion. We also divide each task into roughly a dozen subtasks (947 total), and find
that Gemini 3 achieves the highest subtask success rate of 76.4% but struggles to complete
all subtasks within a given task (only completing 12.9% of tasks end-to-end). Ablations
over the observation space (i.e. vision-enabled vs. DOM-only) and prompting strategy
(i.e. zero-shot vs. informative prompts) show that document handling and cross-portal data
transfer are key failure modes.

BACKGROUND AND RELATED WORK
2.1
COMPUTER-USE AGENTS
Web interaction.
Early web-interaction suites such as MINIWOB++ (Liu et al., 2018) provide
synthetic, templated websites that stress basic UI primitives (clicking, typing, form filling). More
realistic benchmarks move to live websites and richer task instructions. WEBSHOP (Yao et al.,
2023) evaluates end-to-end shopping tasks with grounded actions, while WEBARENA (Zhou et al.,
2023) evaluates instruction following across multiple websites with long-horizon dependencies.
MIND2WEB (Deng et al., 2023) further emphasizes generalization by grounding actions in diverse real webpages and annotated demonstrations. Recent multimodal settings such as WEBVOYAGER (He et al., 2024) introduce screenshot-grounded web navigation, highlighting the gap between DOM-only agents and agents that must interpret rendered UIs. Most recently, REAL (Garg
et al., 2025) provides deterministic, high-fidelity replicas of real-world websites with programmatic
state-diff checks and rubric-guided LLM judgments, enabling reproducible multi-turn web-agent
evaluation.
Enterprise and “workplace” web environments.
A key trend is moving from consumer web
navigation to professional workflows with stricter schemas, business rules, and multi-step procedures. WORKARENA (Drouin et al., 2024) targets enterprise-style tasks (e.g., ticketing/CRM-style
workflows) and emphasizes evaluation under realistic constraints such as authentication, form validation, and high action costs. REAL (Garg et al., 2025) similarly evaluates agents on realistic,
multi-step tasks in deterministic replicas of production websites, with explicit evaluation of state
changes and information retrieval quality. The BrowserGym ecosystem (Chezelles et al., 2025) unifies several of these web-agent suites (including MINIWOB++, WEBARENA, and WORKARENA)
under a common observation/action interface, simplifying large-scale, cross-benchmark evaluation.
OS and multi-application workflows.
Beyond the browser, benchmarks now test full desktop
interaction. OSWORLD (Xie et al., 2024) evaluates multimodal agents on open-ended tasks in real
OS environments, requiring GUI grounding, tool switching, and recovery from errors. These results
suggest that failures often arise from brittle perception-action grounding and incomplete operational
knowledge rather than purely “reasoning” mistakes.
Taken together, these benchmarks motivate healthcare administration environments that resemble
enterprise workflows: agents must execute schema-constrained portal interactions reliably and recover gracefully from invalid actions.

actions, and objective success checks.
2.2
THE CLINICAL V. ADMINISTRATIVE GAP
Most medical AI research focuses on the clinical front-end of care rather than the administrative
infrastructure that supports it.
Clinical reasoning and dialogue.
Benchmarks and evaluation suites such as MultiMedQA (Singhal et al., 2022) and Med-HALT (Pal et al., 2023) probe diagnostic reasoning, clinical question
answering, and safety vulnerabilities. The most recent comprehensive evaluation, MedHELM (Bedi
et al., 2026), assesses LLMs across 121 tasks spanning clinical decision support, patient communication, medical research, and healthcare administration tasks. However, these evaluations are largely
text-based and do not capture the end-to-end, payer-facing transactional workflows (e.g., portal navigation, form completion, and submission) that underpin revenue-cycle operations.

HEALTHADMINBENCH
We define healthcare administration tasks as sequential decision problems over multiple interactive
web portals. Each task is formalized as a partially observable Markov decision process (POMDP),
where the latent state st ∈S encodes the complete configuration of all browser sessions at time t.
This state includes rendered page content, navigation context, and task-relevant statuses such as submitted forms, uploaded documents, and portal-specific workflow progress. Environment dynamics
are deterministic. Given an action at ∈A selected by the agent, the browser automation engine executes the corresponding interaction and transitions the system deterministically to a new state st+1
via a transition function T : S × A →S. At each timestep, the agent receives a partial observation
ot = O(st) ∈O, such as a rendered screenshot of the active portal or a structured representation
of the interface. The agent selects actions conditioned on the task specification and its interaction
history, and advances the environment accordingly. Episodes terminate when the agent signals completion or exceeds a specified interaction budget. Performance is evaluated using a binary terminal
reward rT ∈{0, 1}, indicating whether the administrative objective was completed correctly. Following similar works Garg et al. (2025), all interactions with the environment are mediated through
Playwright, providing a standardized interface for executing user-level browser actions.

information across multiple systems.

3.2
OBSERVATION SPACE
The observation function O(st) specifies the information available to the agent at timestep t.
HEALTHADMINBENCH supports observation modalities that reflect realistic enterprise computer
use. Concretely, observations may consist of: (i) a structured interface representation derived from
the accessibility tree, in which interactive elements are indexed by stable data-testid identifiers, (ii) a rendered screenshot of the current browser viewport, or (iii) both.
The data-testid-indexed representation follows prior computer-use benchmarks Garg et al.
(2025) and lets agents refer to complex UI elements symbolically, without explicit reasoning over
screen coordinates. This aligns with language-based agents that operate primarily over textual or
structured inputs. Screenshot-only observations, in contrast, support computer-use agents that rely
on visual grounding: these agents must infer both the correct action and where to apply it on the
screen.
3.3
ACTION SPACE
We define a finite action space that captures user-level keyboard and mouse operations. Actions
are expressed in natural language and emulate how a human operator interacts with administrative
web portals. For agents with access to the accessibility tree, actions operate on interface elements
addressed by their data-testid identifiers, enabling symbolic selection and manipulation of UI
components. Agents with screenshot-only observations are given the same action set but must also
infer the spatial location of each action.
The action space includes standard browser interactions such as clicking buttons, entering text, selecting dropdown options, toggling checkboxes, uploading or downloading files, and scrolling. A
complete enumeration of supported actions for each environment appears in Table 5.

3.4
TASKS
In line with the MedHELM taxonomy, each HEALTHADMINBENCH “task” is grounded in a MedHELM Administration and Workflow task, and our “subtasks” make its fine-grained, verifiable steps
explicit.
HEALTHADMINBENCH contains 70 tasks spanning the four environments in Section 3.1. Tasks
were designed with expert healthcare administrators and target four common administrative workflows: patient information verification, prior authorization submission, chart-based clinical reasoning, and durable medical equipment (DME) processing. These workflows are among the most frequent and time-consuming responsibilities of revenue–cycle staff.
1. Patient Verification (20 tasks). These tasks require the agent to verify patient-specific
information and document a determination within the EHR, such as determining whether a
visit requires prior authorization, checking appointment dates, and ensuring referrals contain complete documentation. Workflows remain within a single portal and do not require
cross-site navigation.
• Example:
Open the referral for Robert Quinn (60M with Aetna HMO). Before proceeding with the stress echocardiogram authorization, verify that the patient’s insurance coverage status is valid. Document your findings and take appropriate action
2. Prior Authorization (20 tasks). These tasks instruct the agent to submit a prior authorization request, which typically requires gathering EHR information (e.g. diagnosis codes,
authorization letters, provider NPIs), navigating to the correct payer portal, completing the
authorization form, and recording the authorization number in the EHR.
• Example: Open the referral for John Doe and submit a prior authorization request for
a bilateral eye injection to the Payer A portal. Record the authorization number in the
EHR and clear the referral.
3. Clinical Reasoning (20 tasks). These tasks require the agent to reason over clinical information (e.g. medication dosages or referral documentation) in the EHR in order to choose
the correct administrative action.
• Example: Paul Adams requires chemotherapy authorization. Review the clinical notes
to identify the treatment plan and calculate the total number of visits needed for the
full course of treatment. Submit the authorization request for the correct number of
visits and record the authorization number in the EHR.
4. DME Processing (10 tasks). These tasks involve processing durable medical equipment
(DME) orders by downloading documentation from the EHR, creating an eFax submission,
and documenting the result in the EHR.
• Example: Process David Mitchell’s DME order for a CPAP machine. Download the
required documents, fax them to the supplier, add a note, and clear the referral.
3.5
SUBTASKS
Each task in HEALTHADMINBENCH is associated with a fixed set of subtasks that determine success. A trajectory counts as successful only if the agent satisfies all subtasks (100% pass rate),
mirroring the high-stakes nature of administrative workflows where minor omissions can invalidate
an entire submission.
In total, HEALTHADMINBENCH contains 947 distinct subtasks. Of these, 802 are validated with
automated JMESPath-based verifiers that query the final environment state (structured as JSON) to
verify objective conditions (e.g., whether a specific ICD-10 code such as H35.52 appears in a prior
authorization request). The remaining 145 subtasks use LLM-based validation and assess semantic
criteria that are difficult to encode programmatically (e.g., whether a progress note correctly explains
why a prior authorization is not needed). All verifiers return a binary score.
We group subtasks into five categories:
1. Document Handling (142 subtasks). Checks that the agent correctly downloads and uploads required documents across portals, such as retrieving an authorization letter from the
EHR and attaching it to a payer submission.

3.6
MEMORY
HEALTHADMINBENCH comprises tasks that require multiple steps across multiple screens. Most
computer-use agents do not have sufficient context length to provide all past actions and observations
to the model at every step. To address this, we provide models with a scratch space to store longterm information between steps. At each step, we ask the model to provide information that should
be saved. The saved information is then returned to the model in the following steps.
3.7
PROMPTING STRATEGY
As part of running an agent, it is necessary to provide prompts that explain the environment to
the model (including explanations of actions, observations, and information retention). We support
three general strategies for prompting: zero-shot, informative, and task-specific. In the zero-shot
prompting setting, we provide only environment information to the prompt as well as a simple description of the task. In the informative prompting setting, we expand on the zero-shot prompts
to also include general advice on how to perform administrative health tasks. In the task-specific
prompting setting, we expand the informative prompts to also include per-task step-by-step instructions on how to perform the task. See Appendix A for full details of the prompting setup, including
sample prompts.

HEALTHADMINBENCH supports multiple observation and prompting configurations. Unless otherwise noted, all results use accessibility-tree observations with informative prompting.

4.3
ABLATION EXPERIMENTS: PROMPTING AND OBSERVATION
In our primary experiments, we evaluate models using informative prompts and accessibility-tree
observations. To assess the sensitivity of our results to these design choices, we conduct ablation
experiments that vary both the prompting strategy and the observation modalities.
Figure 4 summarizes these ablations.
Specifically, we compare the performance of zero-shot
prompting to informative prompting (see Section A), and evaluate the effect of augmenting
accessibility-tree observations with screenshots, relative to using the accessibility information alone.
We find that replacing informative prompts with zero-shot prompts leads to a substantial degradation
in performance, with large drops in task success rates across all models. This result indicates that
current frontier models struggle to reliably navigate complex, interconnected healthcare administrative environments without additional domain-specific guidance. These findings highlight the importance of informative prompting when applying general-purpose models to specialized domains such
as healthcare administration. In contrast, adding screenshot observations provides limited, if any,
additional benefit when accessibility-tree information is already available.
4.4
QUALITATIVE ANALYSIS OF FAILURE MODES
To better understand where models struggle, we manually reviewed failure traces from Claude Opus
4.5 and confirmed the same patterns across other models. Three categories of errors account for the
majority of failures.
Hidden long-term dependencies.
Many tasks follow a two-phase structure: (i) gather information
in the EHR and (ii) perform data entry in a payer portal or fax system. The difficulty lies in the fact
that the information required in phase (ii) is not always obvious during phase (i). For example, a
payer portal may request a specific document only visible after several form pages. Humans recover
by returning to the EHR and re-gathering missing information, but agents rarely restart and, even
if they do, typically exhaust the step budget. This mismatch between forward-only execution and
latent task dependencies leads to systematic failures.
Avoidance of file downloads and uploads.
Although HEALTHADMINBENCH includes support
for file downloads and uploads, most models hesitate to use these actions or simply ignore them.
Since document transfer is essential for prior authorization and DME workflows, this single behavior causes widespread failure in document-handling subtasks. Gemini 3 is the notable exception,
exhibiting reliable use of download and upload actions.
Information loss over long horizons.
Unlike humans, who naturally retain all prior observations,
computer-use agents often operate with strict context limits. Only the most recent accessibility trees

DISCUSSION
We introduced HEALTHADMINBENCH, a benchmark for evaluating computer-use agents on realistic healthcare administrative workflows spanning multiple enterprise systems. Across six frontier
models, end-to-end task success remains low—the strongest model (Claude Opus 4.5) reaches only
22.9%—despite much higher subtask pass rates. Performance varies sharply by workflow type, and
most failures stem from document handling and cross-portal information transfer. These findings
highlight a substantial gap between current agent capabilities and the reliability required for realworld revenue-cycle operations.
Limitations.
While our environments and task set capture key sources of structural difficulty in
healthcare administrative web workflows, they remain simplified proxies for production systems and
do not reflect the full variability of payer policies or interface drift over time. Agents operate under
limited context windows, leading to information loss over long horizons even with scratch space. We
evaluate single-shot trajectories without human-like recovery patterns, and results remain sensitive
to prompt design and action abstractions.
Broader impact.
Administrative workflows drive major cost, delay, and burnout, and health systems increasingly prioritize them for AI automation Muhammad (2026). But premature deployment
of agentic systems risks operational errors with financial or clinical consequences. Benchmarks
like HEALTHADMINBENCH enable more rigorous pre-deployment assessment and highlight areas
where human oversight is still necessary.
Future directions.
Promising directions include fine-tuning agents on HEALTHADMINBENCH
using dense subtask signals, incorporating explicit planning and recovery, and developing stronger
memory and document-aware representations. In addition, supporting and evaluating human-in-theloop workflows for healthcare administrative tasks represents an important avenue for research, as
our results suggest that full automation remains infeasible with current frontier models. Extending
the benchmark to support UI variability, policy changes, and multi-agent workflows would further
improve realism. We welcome community contributions of new tasks and environments.
